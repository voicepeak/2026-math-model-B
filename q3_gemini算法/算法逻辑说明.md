# q3_gemini 算法逻辑说明（问题三 · 全向干扰源）

> 本文件只描述 `q3_gemini算法/` 内代码实际执行的逻辑，不含任何改进建议。
> 代码文件：`strategy.py`（顶层策略）、`robot_core.py`（动作层 + 认证定位内核）、`geometry.py`（几何）、`robot_client.py`（HTTP 协议）、`run_robot.py`（入口）。

---

## 1. 总体流程

策略名：**正六边形 7 点极小覆盖 + 多信道全息批感知 + 正交基线快速交会 + 环形推进**。

```
/enter 进入 (0,0)，频道 1
        │
        ▼
阶段1：原点 (0,0) 批量感知全部存活信道        ← _batch_sense
        │  命中 near  → 原地 clear
        │  命中 direction → 记录 (位置, 示向度)
        ▼
按示向度升序，逐个目标执行交会清除            ← _engagement
        │  第二测点 = 前出 700 m + 侧移 ±450 m  ← _orthogonal
        │  两次测向交会；若已认证(r≤19.9m) → clear
        │  否则进入迭代认证定位                    ← localize_poly
        ▼
阶段2：外圈 6 个六边形顶点依次环形推进          ← hex_scan_nodes()[1:]
        │  每个节点再做一次批量感知，并清除新发现目标
        ▼
cleared ≥ 16 → 提前结束(complete_upper_bound)
否则走完外圈 → 结束(complete_coverage)
```

`strategy.py` 的 `Strategy.run()` 就是上述两阶段；`robot_core.py` 提供被复用的动作与定位内核。

## 2. 覆盖拓扑：7 点正六边形

`strategy.py::hex_scan_nodes()`

- 中心点：`P0 = (0, 0)`
- 外圈 6 点：`Pk = R_HEX · (cos(kπ/3), sin(kπ/3))`，`k = 0..5`，`R_HEX = 1200.0 m`

即：正东、东北、西北、正西、西南、东南 6 个顶点。

### 覆盖论证（代码注释依据）
目标区域为半径 1800 m 圆盘，干扰源有效接收半径 `R ≥ 1000 m`。

1. **内圈 `d = |G| ≤ 1000 m`**：`|G − P0| = d ≤ 1000 m`，原点必可见。
2. **外圈 `1000 < d ≤ 1800 m`**：六边形相邻顶点张角 60°，任意方向到最近顶点的角向偏差 `≤ 30°`。取最近顶点 `P`，则

   ```
   |G−P|² = d² + 1200² − 2·d·1200·cos30°
          ≤ d² − 1200√3·d + 1440000
   ```

   在 `d ∈ [1000,1800]` 上该二次函数最大值出现在端点 `d = 1800`：

   ```
   |G−P|max = √(1800² + 1200² − 2·1800·1200·cos30°)
             = √938770.3 ≈ 968.90 m < 1000 m
   ```

因此 7 个点对 `R ≥ 1000 m` 的全向源构成**无死角覆盖**（最坏盲区 968.90 m）。

## 3. 批量全息感知 `_batch_sense(pos)`

```python
def _batch_sense(self, pos):
    found = {}
    chs = sorted(self.active, key=lambda c: (c != self.client.channel, c))  # 当前频道优先
    for ch in chs:
        res = self.action('measure', pos, ch)
        if res['measure_result'] == 'near':
            self.action('clear', pos, ch); self.active.discard(ch)
        elif res['measure_result'] == 'direction':
            found[ch] = res['svd_deg']
    return found
```

- `self.active` 初始为 `{1..20}`，只对“尚未清除”的频道检测。
- 排序键：**当前测向机频道优先**（省 1 s 切频），其余按频道号升序。
- `near`：距离 ≤5 m，直接原地 `/clear`，从 `active` 移除。
- `direction`：把 `(位置, 示向度)` 暂存到 `found`，供后续交会，不立即清除。
- 时间成本：`Σ (5 s + 切频 1 s)`；20 个频道约 120 s，换取该点的全场方位态势。

## 4. 正交基线第二测点 `_orthogonal(s1, θ1)`

```python
u = unit(θ1); v = (-u[1], u[0])          # u：示向射线方向；v：其法向
b = s1 + 700·u                            # 沿射线前出 700 m
c1 = b + 450·v ; c2 = b − 450·v           # 再向两侧各偏移 450 m
return c1 if |c1| ≤ 1750 else (c2 if |c2| ≤ 1750 else 距原点较近者)
```

设计目标：使第二测点相对目标的两条示向线交会角接近 90°（正交）。

- 射线角误差 `α = 1.005°`，两次测向后的误差区域近似小菱形，其最大对角线
  `D ≈ 2·d2·sinα / sinβ`；当交会角 `β ≈ 75°~90°`、`d2 ≈ 500 m` 时，`D ≈ 18 m`，
  对应外接圆半径 `≈ 9 m ≪ 19.9 m`。
- 前出/侧移量（700 / 450）使目标到第二测点距离一般落在 `300~800 m`，仍在接收半径内。
- `|·| ≤ 1750` 用于避免第二测点跑到任务圆域之外。

## 5. 楔形交会定位（几何内核）

`geometry.py`：

- **单次观测可行域** `prior(s, θ, α)`：以正方形为初值，依次用
  - 目标圆域 `B(0,1800)` 的 128 边外切多边形、
  - 接收圆 `B(s,1500)` 的 128 边外切多边形、
  - 示向楔形 `wedge(s, θ, α)` 的两个半平面

  裁剪得到凸多边形。`α = 1.005°`（题目误差上限 1° + 0.005° 覆盖接口两位小数舍入）。
- **增加一次观测** `clip_wedge(poly, p, θ, α)`：用新楔形的两个半平面再次裁剪，得到交集
  `P_{k+1} = P_k ∩ W(p, θ)`。
- **不确定性度量** `enclosing_circle(poly)`：精确求多边形**最小包围圆** `(c, r)`（枚举顶点/两点/三点候选圆心）。

`_engagement(ch, s1, θ1)` 中的使用：

```python
poly = prior(s1, θ1, ALPHA)
pos2 = _orthogonal(s1, θ1)
res  = measure(pos2, ch)
if res == near:  clear(pos2, ch)
if res == direction:
    poly = clip_wedge(poly, pos2, res.svd_deg, ALPHA)
    c, r = enclosing_circle(poly)
    if r ≤ 19.9: clear(c, ch)          # 两次测向即认证
    else:        localize_poly(...)    # 继续迭代
```

## 6. 认证清除与迭代收敛 `localize_poly`（`robot_core.py`）

```python
for _ in range(4):
    c, r = enclosing_circle(poly)
    if r ≤ 19.9:                     # 认证条件
        clear(c); return
    p = default_viewpoint(poly, s0, θ0, last, last_θ)   # 见下
    res = measure(p)
    if res == near: clear(p); return
    if res == no_signal: break
    poly = clip_wedge(poly, p, res.svd_deg, ALPHA)
# 4 次仍不收敛 → 条带回退
```

- **认证判据 `r ≤ 19.9 m`**：真实源必在该最小包围圆内，故清除点 `c` 与真源距离 `< 20 m`，
  满足 20 m 清除半径，理论必命中。这是整个策略的安全底线。
- **默认迭代补测点** `default_viewpoint`（旧算法沿用）：

  ```
  offset = max(40, min(300, 0.2·diameter))
  候选 = 包围圆圆心 ± offset·v(last_θ)
  排序键 = (是否 guaranteed 接收, 距上一个测点距离, 坐标)
  ```

- **`guaranteed`**：在 `α` 误差、距离 `r∈[5,1500]` 连续范围内都能接收到信号时才优先。
- **`near`**：距离 ≤5 m，直接原地清除。
- **`no_signal`**：说明选点可能超出接收半径，跳出进入回退。

### 条带回退 `fallback_points`
当 4 次迭代无法把 `r` 压到 19.9 m：沿**第一次观测** `(s0, θ0)` 建局部坐标系，生成
长度 `[0,1500] m`、半宽 `w = 1500·sin(1.005°) ≈ 26.31 m` 的双排蛇形共 **110 个清除点**，
逐点 `/clear`，成功即停。用于完整性兜底。

## 7. 状态与终止条件（`strategy.py`）

- 状态集合：`self.active`（未清除频道）、`self.cleared`（`StrategyBase.action` 在
  `/clear` 返回 `success` 时加入）。
- 发现与清除解耦：批量感知只“发现”，`_engagement`/`localize_poly` 才“清除”。
- 终止：
  - `len(cleared) ≥ 16`（题目上限）→ `status = "complete_upper_bound"`，立即返回；
  - 走完原点 + 6 个外圈节点 → `status = "complete_coverage"`；
  - 触发预算/异常 → 返回对应状态（`robot_core.BudgetStop`）。

---

## 8. 动作与计时层 `StrategyBase.action`（`robot_core.py`）

每次 `/measure`、`/clear` 都经过同一入口：

1. 现实预算检查：`client.time_left() < 30 s` → 抛 `BudgetStop('real_time_budget')`；
2. 虚拟预算检查：`virtual_time + dist/5 + 6 > 359000` → `BudgetStop('virtual_time_budget')`；
3. 发送请求；校验 HTTP 状态、`accepted=true`、结果码合法（`direction/near/no_signal`、
   `success/no_target_in_range`）；`direction` 时校验 `svd_deg` 为 `[0,360)` 有限数；
4. 记录轨迹 `trace`，累加 `measure_count` / `clear_count`，`success` 时写入 `cleared`。

时间规则由 `robot_client.py` 与模拟器共同决定：移动 `距离/5 s`、检测 `5 s`、切频 `1 s`、
清除成功 `5 s` / 未命中 `3 s`；`/clear` 不切频。
